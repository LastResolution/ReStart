# 設定の移行と復元

[English](../migration.md)

通常のデータは `%LOCALAPPDATA%\ReStart\layout.json` です。プレビューの保存先は実行ファイル隣に分離します。

v0.5 は schema 3 を保存し、保存したアプリの版と直近の移行記録を持ちます。schema 1/2 の設定・名前・ID・起動先を保持し、対応する値を正規化します。名前なしでタイル1個だけの旧グループは、見出しのない単独タイルへ移行します。名前付きグループは保持します。

最初の置き換え前に読み込み元をバイト単位で `layout.json.schema1-<id>.bak` または `layout.json.schema2-<id>.bak` へ保全します。同じ schema 内でアプリの版が変わる場合も `layout.json.upgrade-<id>.bak` を残します。通常の直前保存 `layout.json.bak` とは別で、後続保存により更新されません。必要な保全に失敗した場合は本体を書き換えません。壊れた本体から旧 .bak を復旧した場合も、復旧元を保全します。

設定 → レイアウトとデータに、移行元・移行先のアプリ版と schema、日時、復元用ファイルを表示します。保存元の版がない旧ファイルは旧形式 / 不明と表示します。

将来の schema と、現在より新しいアプリが保存したファイルは上書き禁止です。v0.2～0.4 は schema 3 を扱えないため、旧版に戻すには対応するバックアップが必要です。

## 旧版に戻す

1. 通知領域から ReStart を終了します。
2. 現在のレイアウトと自作 JS パッケージを別途保全します。
3. 戻したい版に対応するバックアップを選びます。
4. 同じデータフォルダーの `layout.json` としてコピーします。
5. 旧版を起動します。実行ファイルの場所を変えた場合は自動起動も再設定します。

schema の数字だけを書き換えて読み込ませないでください。レイアウトの入出力には JS 本体や Windows 資格情報は含まれません。破損ファイルは .corrupt-日時 として保持し、利用可能なら直前バックアップを読みます。将来形式の原本は変更しません。
